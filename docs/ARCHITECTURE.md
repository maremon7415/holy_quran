# Noor Quran — architecture & conventions

## Stack
Next.js 16 (App Router, React 19, Turbopack), Tailwind CSS v4 (tokens in `app/globals.css`), framer-motion, zustand, cmdk, vaul, radix/shadcn primitives in `components/ui/*`.

## Data
- `data/quran/` — full Quran corpus committed to the repo, generated by `node scripts/fetch-quran-data.mjs` from the open Quran.com (Quran Foundation) API v4.
  - `chapters.json` (114 chapters incl. EN/BN short summary), `surah/<id>.json` (verses), `info/<id>.json` (long chapter intro, HTML), `juzs.json`.
  - Verse record keys: `n` ayah number, `k` "2:255", `ar` Uthmani, `sim` simple Arabic, `en` Saheeh Intl, `enH` Abdel Haleem, `bn` Taisirul Quran, `tl` transliteration, `j` juz, `p` page, `h` hizb, `r` ruku, `s` sajdah.
- Server access: `lib/quran/data.ts` (`server-only`): `getChapters/getChapter/getVerses/getVerse/getChapterInfo/getJuzs/getJuzVerses/getVersesByRefs/parseRef`.
- Client-safe: `lib/quran/chapters.ts` (`chapters`, `surahNamesBn`, `resolveChapterId`, `surahHref`, `readerHref`, `juzHref`, `toArabicDigits`, `toBanglaDigits`), `lib/quran/types.ts`, `lib/quran/normalize.ts`.
- Runtime (client) enrichments come from public CORS-enabled APIs:
  - Word-by-word, tajweed HTML, tafsir: `https://api.quran.com/api/v4/...`
  - Audio + word timing segments: `https://api.qurancdn.com/api/qdc/audio/reciters/{id}/audio_files?chapter={n}&segments=true`
  - Per-ayah audio: `https://everyayah.com/data/<folder>/SSSAAA.mp3`
- Full-text search: `GET /api/search?q=&limit=` (`lib/quran/search.ts`).

## URLs (canonical)
`/surah/{slug}` (e.g. `/surah/al-baqarah`), `/surah/{slug}/{ayah}`, `/juz/{n}`. Always build links with `surahHref()` / `readerHref()`.

## AI & agent surfaces
- `lib/api/corpus.ts` (`server-only`) is the single read-only service behind the JSON API (`app/api/v1/*`, helpers in `lib/api/http.ts`, spec in `lib/api/openapi.ts` → `/openapi.json`), the MCP server (`lib/mcp/server.ts` → `app/api/mcp/route.ts`) and the markdown alternates (`lib/api/markdown.ts` → `app/md/[...path]`, reached via `<page>.md` rewrites in `proxy.ts`). Every result carries `url` (canonical page) + `citation`.
- New MCP tools: register them in `createMcpServer`; non-Quran corpora implement an interface in `lib/mcp/extensions.ts` and are wired in `lib/mcp/providers.ts` (hadith: `HadithProvider`).
- Citations: `lib/content/cite.ts` + `<CiteThis>` (`components/seo/cite-this.tsx`). Answer-first snippets: `lib/content/answers.ts`. schema.org builders: `lib/seo/structured.ts` (surah `sameAs` from the verified `lib/seo/wikidata-surahs.json`).
- Metadata: pass `markdown: true` to `buildMeta` (or `alternates.types = markdownAlternate(path)`) on pages that have a `.md` twin.

## Design system
- Themes (next-themes, class on <html>): `light` (Pearl), `sand` (Parchment), `dusk`, `dark` (Midnight), `black`. The `dark:` variant applies to dusk/dark/black.
- Use semantic tokens only: `bg-background bg-card bg-surface-2 bg-muted bg-accent text-foreground text-muted-foreground text-primary text-gold bg-gold-soft border-border text-arabic`. Never hard-code hex colours in components (except icon art).
- Utilities: `glass`, `card-soft`, `lift`, `text-gradient-gold`, `bg-pattern` (decorative girih tile, put on an absolutely-positioned div), `shimmer` (skeleton), `no-scrollbar`, `pulse-ring`.
- Fonts: `font-sans` (Manrope), `font-display` (Fraunces – headings), `font-arabic` (user-selected Quran font), `font-bangla`, `font-kufi`.
- Quran text: `.quran-text` class (RTL, line-height, colour) sized with `text-[length:var(--quran-size,34px)]`; translations sized with `text-[length:var(--trans-size,17px)]`. Ayah end marker: `<span className="ayah-marker">{toArabicDigits(n)}</span>`.
- Translation blocks carry `data-tr="en" | "bn" | "tl" | "bt"` so the reader preferences (set on <html> before paint) can hide them. Surah/juz pages server-render Arabic + Saheeh + Bangla + Bangla uccharon (`bt`, `data/quran/uccharon/{n}.json`, generated by `scripts/build-bn-uccharon.mjs`); Abdel Haleem + Latin transliteration are fetched on demand from `/quran/data/{n}` and remain server-rendered on single-ayah pages.
- Verse markup is minimal: the per-ayah toolbar, word spans (`.w[data-w]`, only for the recited ayah), tajweed/wbw slots and extra translations (Quran.com catalogue, `useReader().extraTr`) are added client-side by `components/reader/verse-enhancer.tsx`, `reader-controller.tsx` and `arabic-layers.tsx`.
- Icons: custom PNG set — `<UiIcon name="quran" size={24} />` (`components/ui-icon.tsx`), names listed in `public/icons/ui/index.json`. `lucide-react` is OK for tiny utility glyphs (chevrons, x, play/pause inside buttons).
- Motion: framer-motion with spring transitions (`stiffness ~380, damping ~30`), `ease-[var(--ease-soft)]` for CSS. Respect reduced motion (MotionConfig is set globally).
- Radius: cards `rounded-3xl`, chips `rounded-full`.

## i18n
- UI languages `en | bn | ar` (`useAppStore().language`). Client: `const t = useTx(); t({ en: 'Read', bn: 'পড়ুন', ar: 'اقرأ' })` (falls back to `en`). Pure/server-safe picker: `pick(lang, v)` in `lib/i18n/t.ts` (+ `bnNum`).
- **Bangla URLs**: every main content page has a server-rendered twin under `/bn/...` (same slugs). Twin routes are listed in `BN_ROUTES` (`lib/i18n/routes.ts`); helpers `localeHref(locale, path)`, `alternatesFor(path, locale)`, `hasBnTwin`, `stripLocale`, `isBnPath`.
  - Page bodies live in `components/pages/<name>.tsx` as `XPage({ locale })` + `xMeta(locale)`; `app/x/page.tsx` and `app/bn/x/page.tsx` are thin wrappers (segment config like `revalidate`/`dynamicParams` stays in each page file).
  - `buildMeta({ ..., path: '/x', locale })` emits the canonical + `alternates.languages` (en/bn/x-default) automatically for twin routes. `Breadcrumbs`/`Faq`/`AyahCard` take `locale`.
  - `app/bn/layout.tsx` (nested, not root) wraps pages in `LocaleProvider locale="bn"`. `useLang()` returns the URL locale first (provider, else `/bn` pathname — the shell lives outside the bn layout), then the store.
  - Links: in client components use `import Link from '@/lib/i18n/link'` (keeps users inside `/bn` when a twin exists) or `useLocalizedHref()`; in server pages use `localeHref(locale, href)`.
- **Arabic** is UI-only (no URLs), RTL. `lib/i18n/script.ts` (`localeScript`, runs before paint after the reader prefs script) sets `<html lang dir class="lang-ar">`; `HtmlLangSync` keeps it in sync. Use logical Tailwind utilities (`ms/me ps/pe start/end text-start/end rounded-s/e border-s/e`) and `rtl:rotate-180` on directional arrows/chevrons. Quran text keeps explicit `dir="rtl"`; English/Bangla content blocks (`lang="en|bn"`, `data-tr`) stay LTR inside the RTL UI via CSS.

- **Arabic content**: hand-written content carries Arabic names — `data/content/ar.ts` (`topicAr`, `duaTitleAr` = mostly the opening words of the dua, `asmaMeaningAr` for the 99 Names) is merged into `topics` / `duas` / `asmaUlHusna` (`t.ar`, `d.title.ar`, `n.meaningAr`); famous-ayah names have `ar` in `lib/reader/famous.ts`; reciters have `ar` + `reciterName/Style/Note(lang, …)`; hadith/Quran citations go through `sourceFor(lang, source)` (`lib/i18n/source-names.ts`) and refs through `refLabelFor(lang, '2:255')`. Long editorial copy (topic intros, dua *when/virtue*, name explanations, FAQ answers) and the English/Bangla *translations* stay in their language by design.
- **Server pages in Arabic**: server components can't read the language, so wrap text in `<T en bn ar />` / `lt(locale, {…})`, hide Bangla/English glosses with `<NotAr>` (`lib/i18n/text.tsx`), use `<SurahName id />`, `<SurahMeaning id />`, `<RefLabel r />`, `<Source s />` (`lib/i18n/surah-name.tsx`, `source.tsx`). Localised `aria-label` / `title` on server-rendered elements: `<Labelled as="nav" label={{en,bn,ar}}>` / `<Titled>` (`lib/i18n/labelled.tsx`); for hundreds of repeated elements (ayah numbers/markers) ship `data-ar-title` / `data-ar-aria` and let `AttrLocalizer` swap them (no client component per ayah). Don't edit `app/globals.css` for these — use the components above.
- **Audit**: load a route with `localStorage['quran-store'] = {"state":{"language":"ar"}}` (or visit `/bn/…`) and list visible text/aria/title that still contains Latin letters; what remains is proper names (reciters, translators, fonts), transliterations and English translations.
- **`<html lang>` on `/bn`**: the root layout is shared, so the server HTML of `/bn/*` still says `<html lang="en">`; the pre-paint `localeScript` and `HtmlLangSync` set `lang="bn"` before first paint. Mitigations that need no second root layout: `app/bn/layout.tsx` emits `<meta http-equiv="content-language" content="bn">` (hoisted into `<head>`) and wraps content in `<div lang="bn">`, and the pages carry `hreflang` alternates, so crawlers/screen readers see Bangla for the content. A fully static `<html lang="bn">` needs two root layouts via route groups (`app/(en)/layout.tsx` + `app/(bn)/layout.tsx`, a shared `components/shell/root-shell.tsx`, `experimental.globalNotFound` + `app/global-not-found.tsx`, `opengraph-image`/`icon` re-declared per group). This was prototyped and builds with all pages still static, but it moves every route directory under `app/(en)/` (collides with parallel work adding top-level routes), loses the auto-injected root `icon.png`/`opengraph-image` inheritance, and makes en↔bn switching a full page load (interrupting the audio player) — so it was not adopted.
- **Offline & Bangla**: downloads cover the UI language's URLs (`/bn/...` for Bangla, `/...` otherwise, Arabic uses English) with an "also download the other language" switch; chosen locales are remembered in `localStorage['noor-offline-locales']`. `public/sw.js` falls back to the `/bn/x` ↔ `/x` twin when only the twin is cached. Updates: a new SW waits (no `skipWaiting`) and `sw-register.tsx` shows an "Update available — Reload" toast; old versioned caches live 24h and are still read by the asset handler; downloaded pages refresh lazily on online visit, and the background refresh is gated on `saveData`/`effectiveType` and throttled to once per 3 days.
- **Bangla OG images** (`app/bn/**/opengraph-image.tsx`, builders in `lib/content/og-pages.ts`, font Hind Siliguri fetched at build with an English fallback): Satori does not shape Indic scripts (pre-base vowel signs ি ে ৈ ো ৌ are not reordered, conjuncts after hasanta are drawn unjoined), so `renderOg(props, { locale: 'bn' })` only renders the Bangla card when the Bangla title passes `bnShapesCorrectly()` (kicker/subtitle lines are dropped individually); otherwise the English card is served. Proper shaping would need HarfBuzz (e.g. `harfbuzzjs` → SVG paths) — not added to avoid a wasm dependency.

## Hadith library (`/hadith`, `/bn/hadith`)
- **Data**: the open [fawazahmed0/hadith-api](https://github.com/fawazahmed0/hadith-api) corpus on jsDelivr (code under the Unlicense; translations/grades belong to their authors; credited on /about). Only compact metadata is committed: `data/hadith/index.json` (~70 KB; collections, books with hadith ranges, counts, grade summary, Muslim's number map, blank "dead" numbers), generated by `node --experimental-strip-types scripts/build-hadith-index.mjs` (downloads into git-ignored `scripts/.cache/hadith`; also validates every curated hadith in `lib/hadith/featured.ts` against the English text). Texts are fetched at request time with `fetch(…, { next: { revalidate: 2592000 } })` (`lib/hadith/fetch.ts`, `.min.json` → `.json` → raw GitHub fallback; failures throw `HadithFetchError`, pages render an error state + noindex, never a 500).
- **Numbering** (`lib/hadith/numbering.ts`): URL number = the commonly cited number (sunnah.com). Bukhari/Abu Dawud/Tirmidhi/Nasa'i/Ibn Majah/Malik/Nawawi/Qudsi = corpus `hadithnumber` (integer part; Bukhari 402 and 402.2 share a page as "402a/402b"). **Sahih Muslim = Muhammad Fu'ad 'Abd al-Baqi number (corpus `arabicnumber`)**, not the corpus running `hadithnumber`; narrations that share it ("2564.01…03") are shown together as 2564a/b/c; the index stores the corpus runs per number. Introduction entries without a number, gaps (63 numbers in Muslim 8–3033) and entries blank in every language are not served (404, not in sitemaps).
- **Routes**: `/hadith`, `/hadith/{collection}`, `/hadith/{collection}/book/{n}` (+ `/page/{p}`, 25 per page), `/hadith/{collection}/{number}`, `/hadith/search?q=&c=&page=` (noindex); all with `/bn` twins. Collections: `bukhari muslim abudawud tirmidhi nasai ibnmajah malik nawawi40 qudsi40` (aliases `nawawi`, `qudsi`, `abu-dawud`… redirect). Single-hadith pages use ISR (`dynamicParams = true`, `generateStaticParams` = curated famous hadiths + first hadith of each book, `revalidate` 6 h so an error state heals quickly; the texts themselves stay cached 30 days). Segment-config exports must be literals (Next rejects imported constants).
- **Server API** (`lib/hadith/index.ts`): `getCollections()`, `getBook()`, `getHadith(collection, number, langs)`, `searchHadith(q, opts)`, `hadithUrl(collection, number, locale)` (+ `collectionUrl/bookUrl/searchUrl`, `isServable`, `neighbours`, `parseHadithSource`, `parseHadithReference`). `getHadith` returns null for unknown numbers (no network call) and throws `HadithFetchError` when the corpus is unreachable.
- **Search** (`lib/hadith/search.ts`): language detected from the query script; each collection/language edition is downloaded once (no Next data cache: they exceed its 2 MB limit), reduced to `{number, text}` rows (Arabic normalised with `lib/quran/normalize.ts`) and kept in a ~70M-character LRU. English = word-prefix match with light stemming, Bangla tolerates ি/ী ু/ূ, Arabic ignores harakat/alef/ya/ta-marbuta variants; all words must match; "Bukhari 1" / "বুখারী হাদিস ১" are recognised as references (`exact`). Prefer `collection` for speed.
- **Dua sources**: `<HadithSourceLink s={d.source} />` (components/hadith) turns "Sahih al-Bukhari 6306; Quran 2:255" into links; hadith pages list the duas that cite them (`lib/hadith/dua-sources.ts`).
- Sitemaps: `lib/hadith/sitemap.ts` → extra `/sitemap/{id}.xml` files after the Quran ones (English then `/bn`, 5,000 URLs each).

## State
- `lib/store.ts` – legacy app store (reading stats, bookmarks `importantAyahs`, progress, language…). Persisted as `quran-store`.
- `lib/stores/reader.ts` – reader prefs (`useReader`). `lib/stores/ui.ts` – palette/more/immersive.
- New features add their own store file under `lib/stores/` instead of editing shared ones.

## Layout
`app/layout.tsx` renders `SiteHeader`, `MobileTabBar` (fixed bottom on < lg — leave ~6rem bottom padding on mobile pages), `SiteFooter`, `CommandPalette`, `PlayerRoot` (global audio player). Pages render inside `<main>`; use `mx-auto max-w-7xl px-4 sm:px-6` containers.

## Testing & CI
- **Unit / API** (`tests/unit`, vitest, `pnpm test`): pure logic in `lib/**`, route handlers called directly (`import { GET } from '@/app/api/search/route'`), data-integrity checks over `data/quran` + `data/content`. `server-only` is aliased to a stub (`tests/helpers/server-only.ts`). Files that need a timezone set `process.env.TZ` at the very top (see `hifz-streak-dst.test.ts`).
- **Added with the i18n work**: unit tests `i18n-routes`, `i18n-content`, `uccharon-data` (+ fixture score ≥ 0.95), `prayer-times` / `prayer-reminders` / `prayer-ics`, `offline-helpers`, `sync-merge-edges`; e2e `i18n`, `reader-extras`, `accounts-offline-prayer`, `sitemaps`. The reader's top bar holds a second, inert “Reading settings” button parked above the viewport — click the one that is not inside `[inert]` (see `reader-extras.spec.ts`).
- **E2E** (`tests/e2e`, Playwright, `pnpm test:e2e`): `baseURL` = `E2E_BASE_URL` (default `http://localhost:3100`). Import `test`/`expect` from `./fixtures` — it stubs third-party hosts, hides the Next dev overlay and exposes `problems` (page errors / console errors). Add a new main route to `MAIN_ROUTES` in `fixtures.ts` to put it under the console-error sweep; add it to `ROUTES` in `a11y.spec.ts` for axe.
- **Conventions**: use roles/labels over CSS selectors; ayahs are `article[data-ayah="67:5"]`; reader prefs are `data-show-en|bn|tl` on `<html>`; persisted stores are in localStorage (`noor-hifz`, `noor-journey`, `noor-reader`, `quran-store`, `theme`). Wait for `networkidle` before interacting right after load (hydration). Never assert on Arabic with literal diacritics — match `/[\u0600-\u06FF]{3,}/`.
- **Bugs**: a failing test that exposes a real bug is committed as `.skip`/`.fixme` with `// BUG: file:line — repro`; un-skip it in the PR that fixes the bug.
- **A11y**: serious/critical axe violations must be fixed or listed in `tests/e2e/a11y-known-issues.json` (the list may only shrink).
- **CI**: `.github/workflows/ci.yml` (typecheck, unit, `validate:content`, build, e2e on chromium) on PRs and `master`; `.github/workflows/content.yml` weekly `verify:hadith`. Run `pnpm check` locally before pushing.
